# Project Rules & Agent Execution Policy

## Subagent Delegation Guidelines
- **Subagent-First Default**: Always prefer delegating codebase exploration, research, and parallel implementation tasks to subagents instead of executing them sequentially in the main thread.
- **Research Subagents (`research`)**:
  - Use for broad codebase reconnaissance, multi-file searches, documentation queries, and reading extensive logs/reports.
  - Keep exploratory file-reading and grep outputs out of the main thread context.
- **Worker / Parallel Subagents (`self`)**:
  - Use when executing independent sub-tasks (e.g., frontend vs. backend changes, unit testing, validation scripts, parallel refactoring).
- **Main Thread Role**:
  - Focus the main conversation thread on synthesis, high-level planning, architectural decisions, and clear direct interactions with the user.

## Android (Capacitor) & Production Deployment Architecture

The ChartsOff project is designed as a **dual-target application**: Web (Vercel) and **Native Android App (Capacitor APK built on GitHub Actions)**. All changes MUST preserve compatibility with both environments:

1. **Serverless Mobile-Ready Data Synchronization**:
   - The app does not rely on a persistent Python backend server in production.
   - Predictions and market features are generated by `.github/workflows/daily_pipeline.yml` (Mon-Fri 09:30 UTC / 16:30 WIB post-market close) and committed to `outputs/latest_predictions.json` and `frontend/public/data/latest_predictions.json`.
   - In production & mobile APK, `frontend/src/hooks/usePredictions.js` queries GitHub Raw CDN (`https://raw.githubusercontent.com/stockfishZ/ChartsOff/main/outputs/latest_predictions.json`) for fresh daily updates, and automatically falls back to bundled APK assets (`/data/latest_predictions.json`) and `localStorage` when offline.

2. **Capacitor Android Build Rules (`build_apk.yml`)**:
   - The Android APK is built by GitHub Actions using `.github/workflows/build_apk.yml`.
   - Build flow: `npm ci` -> `npm run build` (generates `frontend/dist/`) -> `npx cap sync android` (copies `dist/` into `frontend/android/app/src/main/assets/public/`) -> `./gradlew assembleDebug`.
   - Never commit `frontend/dist/` to Git.
   - For any manual or CI commit of bundled mobile assets, remember `frontend/android/.gitignore` ignores `app/src/main/assets/public`. Always use `git add -f` if updating `frontend/android/app/src/main/assets/public/data/latest_predictions.json`.

3. **Data Integrity & Network Guardrails**:
   - **Never use global socket timeouts** (`socket.setdefaulttimeout(...)`) anywhere in Python code; isolate timeouts per-request in `requests` or `feedparser`.
   - **Never implement arbitrary time-based pruning** (e.g. `< 72 hours`) in `StorageManager`. Weekends, market holidays, or partial ticker runs must never wipe out existing valid default stocks. Full runs only prune non-default/test tickers (e.g. `CUSTOM.JK`).
   - Ticker prices in `config.DEFAULT_TICKERS` must always be supported with graceful fallback handling and retry logic in `MarketDataFeed`.
